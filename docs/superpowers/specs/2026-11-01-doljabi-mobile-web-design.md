# 돌잡이 (돌봄길잡이) 모바일 웹 — 설계

**상태:** 초안 · 2026-11-01 · 팀 검토 대기
**목적:** 캡스톤 대회 제출용 모바일 웹앱. **2026-11-01 하루 안에 완성** (팀 결정).
**주제:** 가족돌봄청년의 정보 사각지대 해소를 위한 법령 기반 AI 지원 안내.

## 1. 무엇을 만드나

가족을 돌보는 13~34세 아동·청년이 질문 5단계에 답하면, 받을 수 있어 보이는 국가·지역 지원과 담당 청년미래센터를 법령 근거와 함께 보여 주고,
궁금한 점은 채팅(기존 RAG 챗봇)으로 이어서 묻는 앱.

**성공 기준 (심사 당일)**
- 심사위원이 휴대폰으로 URL을 열고 1분 안에 결과 카드까지 본다.
- 모든 카드와 채팅 답에 근거(법 조문 또는 공식 출처)가 보인다.
- 학교 LLM 서버가 멈춰도 결과 화면은 동작한다.

**하지 않는 것:** 최종 자격 판정 (센터·시군구가 함), 신청 대행, 개인정보 저장, 심리 상담 (위기 신호에는 109 안내),
검수되지 않은 일반 복지사업 목록 (완성 후 시간이 남으면 "더 보기"로 추가, 8절).

## 2. 확정한 결정

| 영역 | 결정 |
|---|---|
| 형태 | 모바일 웹 (홈 화면 추가 가능), 로그인 없음 |

## 3. 데이터

**출처:** 복지로 API(국가 461 · 지자체 4,828건), 온통청년 API(3,843건) 전수 수집 → 가족돌봄 관련 30건 후보 → 팀 검수·결정 → **14건 + 청년미래센터 17곳**.
검수 기록: `data/programs/review/지원사업_검수_2026-11-01_v3.xlsx`, 결정 9개는 같은 이름의 JSON `decisions`.

| 구분 | 사업 |
|---|---|
| 국가 가족돌봄 제도 (6) | 자기돌봄비 · 사례관리(청년미래센터) · 드림스타트(13세 미만) · 일상돌봄(본인부담 경감) · 장기요양 시설급여 이용 지원 · 자활 조건 유예 |
| 청년미래센터 연계 (4) | 국가장학금 · 마을변호사 · 청년도전지원사업 · 청년성장프로젝트 |
| 지역 사업 (4) | 서울형 자기돌봄비(2026 마감) · 충북 · 울산 · 광주 다다름(2026 마감) |
| 센터 | 운영 12 (서울, 부산, 인천, 광주, 대전, 울산, 강원, 충북, 충남, 전북, 대구, 전남) · 준비 중 5 (경기, 경북, 경남, 제주, 세종) |

**표시 규칙**
- 지역 안내가 법령과 다르면 법령 기준으로 쓰고 "지역 안내 표기와 다름"을 붙인다 (예: "연 200만원" → 1회 200만원).
- 마감된 사업은 "2026년 마감 · 다음 모집 예정".
- 확인하지 못한 정보(장기요양 시설급여 신청처, 전남 센터 전화 등)는 "청년미래센터·129에 문의".
- 카드마다 자료 확인일 (2026-11-01).

**파일**
- `data/programs/programs.json`: 앱용 최종 데이터 (검수 JSON에서 생성). 사업마다 id, 구분, 이름, 대상, 소득, 지원 내용, 신청 방법, 기간, 문의, 출처, 확인일, 주의 문구.
- `data/programs/centers.json`: 시·도별 센터 이름, 상태, 전화, 메일.
- `scripts/collect_programs.py`, `scripts/build_programs.py`: 수집·검수 반영 스크립트 (지금은 임시 폴더에 있음, 옮김). 제출 전에 다시 실행해 갱신.
- `data/programs/raw/`: API 원본 (약 15MB) — git에 넣지 않음.

## 4. 화면

시안: `.superpowers/brainstorm/` (flow, questions, results, chat-center, style).

1. **질문 5단계** (버튼으로 답, 모든 질문에 "잘 모르겠어요")
   1. 나: 나이, 시·도·시·군·구 (35~40세면 군 복무 개월)
   2. 돌보는 가족: 관계, 상황 (장기요양 등급 / 심한 장애 / 정신질환 진단 / 6개월 넘게 아프거나 큰 수술 / 그 밖에)
   3. 함께 사는 사람: 같이 사는지 (같이 / 학교·일 때문에 따로 살지만 자주 돌봄 / 따로), 35세 이상 다른 가족과 그 예외
   4. 학교와 일: 지금 하는 일, 돌봄 때문에 힘든 정도
   5. 소득: 수급·차상위 여부, 본인 월 소득 구간 (기준: 2026 1인 가구 중위소득 2,564,238원, 항상 "대략"). 재산은 묻지 않고 "재산도 함께 봐요" 안내
2. **결과**: 내 담당 센터(전화·청년ON) → 국가 제도 → 센터 연계 → 지역 사업 → (자리만) 일반 지원 더 보기 → 다른 지원 찾기(복지로·온통청년·129) → "최종 결정은 센터·시군구"
3. **카드 상세**: 설명, 조건별 ✅❔❌ + 조문, 주의 문구, 신청 단계·서류, 센터 전화, "이 지원에 대해 물어보기"
4. **물어보기**: 진행 단계 표시, 출처 칩, 추천 질문, 카드에서 오면 그 제도 맥락, 109 위기 안내, "답이 틀릴 수 있어요" 안내
5. **센터 찾기**: 내 지역 강조, 운영 12곳, 준비 중 5곳(청년ON·주민센터 안내), 129

## 5. 구조

```
web/ (HTML·CSS·JS, 빌드 없음)  ── 내 정보는 브라우저 localStorage에만, "내 정보 지우기"
  │
app/api.py (Starlette)
  ├─ GET  /                화면 파일
  ├─ GET  /api/programs    programs.json + centers.json
  ├─ POST /api/match       내 정보 → 카드별 상태·조건 (LLM 없음)
  └─ POST /api/chat        질문 + 내 정보 요약 → 진행 단계(SSE) → 답 + 출처 원문
        ├─ src/ragbot/domain/eligibility.py   판정 규칙
        ├─ src/ragbot/domain/programs.py      데이터 읽기·지역/나이 필터
        └─ 기존 Chatbot → 학교 서버 (LLM, bge-m3, 재순위화)
```

**판정 규칙 (eligibility.py)**
- 사업마다 조건 목록: (문구, 근거 조문, 판정 함수). 판정 함수는 ✅/❔/❌.
- 상태: ❌가 하나라도 → 어려워 보여요, 모두 ✅ → 받을 수 있어 보여요, 그 밖 → 확인이 필요해요. "잘 모르겠어요"는 항상 ❔.
- 자기돌봄비·사례관리는 해당하지 않아도 이유와 함께 보여 준다. 나머지는 지역·나이가 맞지 않으면 숨긴다.
- 주요 규칙: 나이 13~34 + 병역 개월 가산 (시행령 제11조①1, 법 제2조1호 단서) · 돌봄대상가족 5가지 (고시 제2조) ·
  35세 이상 가족 예외 7가지 (시행규칙 제6조①) · 주소 예외 (시행규칙 제6조②) · 학업·취업 곤란 (법 제13조①1) ·
  소득 1인 가구 중위소득 100% 대략 비교 (시행령 제11조①2) · 일상돌봄 9~39세, 함께 살기, 자녀 돌봄 제외 · 13세 미만은 드림스타트.

**코어 수정 (최소, 결정 기록 작성)**
- `Chatbot.answer()`에 선택 인자: 진행 콜백, 사용자 맥락 문자열 (시스템 프롬프트에 덧붙임). 기존 호출은 그대로.
- 개인정보: 앱 모드에서는 `runs/` 기록 끄기 (`write_traces=False`, 이미 있음), LLM 응답 디스크 캐시 쓰지 않는 설정 추가 (`CACHE_MODE`에 저장 안 함 모드).
- 도메인 단어는 모두 `domain/`과 `config.yaml`에 (`test_core_is_domain_free.py`).

**챗봇 문서 갱신:** config.yaml 이름 "돌잡이", 시스템 프롬프트에 "사용자 정보가 주어지면 그 상황에 맞춰 답하되 최종 판정은 하지 말 것",
DATA.md의 센터 현황(4곳 → 12곳), 자기돌봄비 소득인정액 제외 등 검수에서 확인한 사실.

## 6. 오류 처리

- LLM 서버 무응답·60초 초과: 채팅에 "지금은 답을 만들 수 없어요" + 센터·129 전화 버튼. 결과 화면은 영향 없음.
- 연결 끊김: 다시 보내기 버튼.
- 입력 누락: 해당 조건 ❔, 앱은 계속 동작.
- 데이터 파일 문제: 서버 시작 시 형식 검사, 실패하면 시작하지 않음 (배포 전에 발견).

## 7. 테스트와 배포

**테스트 (개발 중, 자동)**
- 판정 규칙 단위 테스트: 조건별 경계값 (35세+병역 2년, 38세 형+장애 예외, 12세 → 드림스타트, 따로 삶 → 주소 ❌ 등).
- API 테스트: 세 엔드포인트 형식, 내 정보가 `runs/`·`.cache/`에 남지 않음.
- 기존 `python -m ragbot check --fast` 매 변경마다.
- **채팅 점검 10개** (앱 완성 후): GOAL.md 후보 질문 10개를 `eval/golden_qa.jsonl` 형식으로. 정답 초안과 근거 조문은 Claude가 붙이고 팀이 확인
  (AGENTS.md의 "정답을 에이전트가 처음부터 쓰지 말 것"은 팀 확인을 거치는 것으로 이번에 한해 완화, 결정 기록).
  `python -m ragbot eval` → 틀린 답 원인 수정 (알려진 오답: 38세 형 동거, 군 복무 35세) → 다시 실행, 전후 수치 기록.
  앱 완성이 늦어지면 이 단계부터 생략.
- 템플릿의 20~30개 골든 QA, 통과 기준(thresholds), 사용자 시나리오 점검은 하지 않음 (팀 결정 2026-11-01). AGENTS.md·tasks의 완료 기준을 이에 맞게 고치고 결정 기록 남김.
- 사람: 아이폰 Safari, 안드로이드 Chrome에서 전체 흐름 한 번.

**배포 (Hugging Face Spaces, Docker)**
- 이미지: 앱 + `index/` (로컬에서 빌드) + `data/programs/*.json`. kordoc·Node 불필요.
- 키는 Space Secrets에만. `.env`, `data/programs/raw/`는 이미지에서 제외.
- 배포 후 확인: 해외 서버 → 학교 LLM 서버(Cloudflare) 연결, 임베딩, 재순위화.
- cron-job.org 하루 1회 접속 (48시간 미접속 시 잠듦 방지), 대회 당일 아침 직접 확인.

## 8. 순서 (오늘 하루, 앞 단계일수록 필수)

| 순서 | 개발 | 팀 | 끝났다는 기준 |
|---|---|---|---|
| 1 | 구현 계획, programs.json·centers.json, 판정 규칙 + 단위 테스트 | 설계 문서 확인 | 테스트 통과 |
| 2 | API 3개, 코어 최소 수정, 개인정보 설정, 인덱스 빌드 | 전남 센터 전화 확인 | 로컬에서 API 응답 |
| 3 | 화면: 질문 5단계, 결과, 상세, 센터 찾기 | 내 PC 브라우저로 확인 | 질문 → 결과까지 동작 |
| 4 | 채팅 화면 (진행 단계, 출처 칩, 내 정보) | 써 보고 피드백 | 채팅 답과 출처 표시 |

| 7 | 챗봇 문서 갱신 (이름, DATA.md 센터 현황), 결정 기록 | — | `check --fast` 통과 |

늦어지면 6 → 7(문서 일부) 순으로 줄인다. 나중에 할 것: "일반 지원 더 보기" (공공데이터 자동 정리 + 표본 검수, 약 하루).

## 9. 남은 확인 (개발을 막지 않음)

- 전남청년미래센터 전화번호, 대구 번호 공식 확인
- 장기요양 시설급여 이용 지원의 신청처·서류
- 드림스타트를 아동 본인이 신청할 수 있는지, 충북 가족돌봄 탭 내용, 서울형 금액 표기 차이
- 센터 미설치 지역의 자기돌봄비 실제 지급 절차 (앱은 "구청에 확인"으로 안내)
- 사례관리 카드의 청년ON 원문 인용("통합돌봄·장기요양·일상돌봄 연계")을 그대로 둘지
